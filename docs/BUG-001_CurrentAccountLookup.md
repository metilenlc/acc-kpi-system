# BUG-001 — Текущий аккаунт не найден в реестре

## 1. Цепочка вызовов

Основной пользовательский сценарий:

```text
onOpen()
└── buildUserMenuV1_()
    └── пункт меню «Найти текущий аккаунт (в реестре)»
        └── findCurrentAccountV1()
            ├── SpreadsheetApp.getActiveSpreadsheet()
            ├── ss.getActiveSheet()
            ├── ss.getSheetByName("ACCOUNTS")
            ├── reg.getRange(...).getValues()
            └── сравнение значения реестра с currentSheet.getName()
```

Пункт меню объявлен в `09_Menu.js`, а обработчик `findCurrentAccountV1()` находится в `11_Accounts.js`. Имя обработчика передаётся меню строкой, поэтому прямого JavaScript-вызова `findCurrentAccountV1()` из другого модуля нет.

Прочитанные `Navigation.js` и `Directory.js` пусты. `15_Directory.js` содержит только заглушку `myFunction()`; `13_Groups.js` и `14_Validation.js` в этой цепочке поиска не участвуют.

## 2. Источник имени текущего листа

В `findCurrentAccountV1()` текущий лист определяется так:

```javascript
const ss = SpreadsheetApp.getActiveSpreadsheet();
const currentSheet = ss.getActiveSheet();
```

Сравниваемое имя каждый раз получается прямым вызовом:

```javascript
currentSheet.getName()
```

Это техническое имя вкладки Google Sheets, например `ACC_001_IG_account`. Значение паспорта аккаунта, ячейка листа или запись из колонки D реестра для определения текущего имени не используются.

## 3. Используемый лист реестра

Поиск выполняется на листе:

```javascript
ss.getSheetByName("ACCOUNTS")
```

То есть используется лист `ACCOUNTS` активной таблицы. В данной функции имя реестра задано строковым литералом, а не `SHEETS.ACCOUNTS`.

Ожидаемая структура реестра документирована в `registerAccountV1_()`:

| Колонка | Содержимое |
|---|---|
| A | ID записи |
| B | SheetId |
| C | Техническое имя листа |
| D | Название аккаунта |
| E | Соцсеть |
| F | Ответственный |
| G | Статус |
| H | Дата создания |
| I | Дата обновления |

## 4. Сравниваемые колонки

Фактически `findCurrentAccountV1()` читает **колонку B**:

```javascript
const names = reg.getRange(2, 2, lastRow - 1, 1).getValues();
```

Аргументы диапазона означают:

- первая строка — `2`;
- первая колонка — `2`, то есть B;
- количество строк — `lastRow - 1`;
- количество колонок — `1`.

Однако техническое имя листа хранится в **колонке C**. Это подтверждается тремя независимыми местами в `11_Accounts.js`:

- комментарий структуры `registerAccountV1_()`: `C - Лист`;
- запись `sheet.getName()` третьим элементом строки реестра;
- `openSelectedAccountV1()` читает техническое имя через `registry.getRange(row, 3)`.

## 5. Сравниваемые значения

Текущее условие:

```javascript
if (names[i][0] === currentSheet.getName()) {
```

Слева находится значение колонки B:

```text
sheet.getSheetId()
```

Обычно это числовой идентификатор вкладки, например:

```text
123456789
```

Справа находится строковое имя активной вкладки:

```text
ACC_001_IG_account
```

Фактическое сравнение имеет вид:

```text
123456789 === "ACC_001_IG_account"
```

Оно не может дать совпадение ни по значению, ни по типу. Требуемое сравнение по текущей логике должно быть между колонкой C и `currentSheet.getName()`:

```text
"ACC_001_IG_account" === "ACC_001_IG_account"
```

## 6. Все этапы нормализации

В проблемном пути `findCurrentAccountV1()` нормализация отсутствует полностью:

1. `currentSheet.getName()` используется без `String()`.
2. К имени листа не применяется `.trim()`.
3. Регистр имени не меняется.
4. Значения реестра читаются через `.getValues()`, без преобразования к строке.
5. К значению `names[i][0]` не применяется `.trim()`.
6. Сравнение выполняется строгим оператором `===`.

При записи реестра в `registerAccountV1_()` также нет нормализации этих двух полей:

- колонка B получает результат `sheet.getSheetId()`;
- колонка C получает результат `sheet.getName()`.

Для сравнения корректно выбранного значения колонки C дополнительная нормализация обычно не нужна: `sheet.getName()` при регистрации и `currentSheet.getName()` при поиске возвращают строки технического имени листа.

Для сравнения: обратная навигация `openSelectedAccountV1()` читает колонку C через `getDisplayValue()`, затем применяет `String(...).trim()`. Эта нормализация относится к другому сценарию и не используется в `findCurrentAccountV1()`.

## 7. Точное место отказа

Ошибка возникает в `11_Accounts.js` внутри цикла `findCurrentAccountV1()`:

```javascript
const names = reg.getRange(2, 2, lastRow - 1, 1).getValues();

for (let i = 0; i < names.length; i++) {
  if (names[i][0] === currentSheet.getName()) {
    // Этот блок не выполняется.
  }
}
```

Первичная ошибка находится в выражении `getRange(2, 2, ...)`: индекс колонки `2` выбирает B вместо C. Непосредственно lookup проваливается в условии `names[i][0] === currentSheet.getName()`, потому что на каждой итерации сравниваются разные сущности.

После исчерпания цикла выполняется единственное найденное в проекте сообщение:

```javascript
SpreadsheetApp.getUi().alert("Текущий аккаунт не найден в реестре.");
```

Поиск по строкам `"Текущий аккаунт не найден"` и `"не найден в реестре"` нашёл только это место в `11_Accounts.js`.

## 8. Корневая причина

Корневая причина — ошибочный индекс колонки при чтении реестра.

`findCurrentAccountV1()` ожидает массив имён листов, что видно по имени переменной `names`, но читает колонку B с `SheetId`. Затем числовой `SheetId` сравнивается со строковым именем активного листа. Регистрация аккаунта работает согласованно со схемой и записывает имя в колонку C; дефект находится именно на стороне чтения в `findCurrentAccountV1()`.

Это не связано с:

- `getActiveAccountSheetV1_()` из `14_Validation.js` — функция здесь не вызывается;
- группировками из `13_Groups.js`;
- `Navigation.js`, `Directory.js` или `15_Directory.js` — рабочей реализации поиска в них нет;
- отсутствием регистра как такового, если лист `ACCOUNTS` существует и содержит строки.

## 9. Минимальное исправление

Минимальная правка — читать колонку C, изменив только индекс начальной колонки с `2` на `3`:

```javascript
const names = reg.getRange(2, 3, lastRow - 1, 1).getValues();
```

Остальная логика может остаться без изменений. Тогда `names[i][0]` будет содержать то же техническое имя, которое записывает `registerAccountV1_()` и использует `openSelectedAccountV1()`.

Альтернативный технически корректный вариант — оставить колонку B и сравнивать её с `currentSheet.getSheetId()`. Однако он меняет смысл переменной `names` и отличается от уже принятого навигационного контракта через колонку C. Для минимального и согласованного исправления предпочтительна замена `2` на `3`.

В рамках этой задачи исправление в JavaScript не вносилось.

## 10. Риски регрессии

1. **Устаревшее имя в колонке C.** Если вкладка была переименована вручную после регистрации, поиск по имени не найдёт строку. Поиск по стабильному `SheetId` устойчивее к переименованиям.
2. **Пустая колонка C.** Предварительно созданные или неполные строки `ACCOUNTS` могут не содержать технического имени листа.
3. **Дублирующиеся имена в данных.** Google Sheets не допускает две вкладки с одинаковым именем, но в колонке C могут сохраниться дубли или устаревшие записи; функция выберет первое совпадение.
4. **Формулы и пробелы в колонке C.** `getValues()` и строгое сравнение не нормализуют ручные значения. Лишние пробелы приведут к несовпадению.
5. **Изменение схемы реестра.** Индекс `3` остаётся magic number; вставка или перестановка колонок снова сломает поиск.
6. **Служебный активный лист.** Функция отдельно исключает только `ACCOUNTS`. При запуске с другого служебного листа она покажет то же сообщение о ненайденном аккаунте, хотя лист не является аккаунтом.
7. **Проверка только счастливого пути.** После исправления нужно проверить как минимум существующий аккаунт, переименованный лист, пустую C, служебный лист и строку, отсутствующую в реестре.
8. **Несогласованность двух направлений навигации.** `openSelectedAccountV1()` использует нормализованное отображаемое значение C, а `findCurrentAccountV1()` — сырое значение. При формулах или нетипичных данных поведение может различаться.

Рекомендуемый регрессионный тест: создать аккаунт штатным `createAccountV1()`, убедиться, что `registerAccountV1_()` записал SheetId в B и имя в C, открыть созданную вкладку, выполнить пункт меню поиска и проверить активацию соответствующей строки `ACCOUNTS`.
