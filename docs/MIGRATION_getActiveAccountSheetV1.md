# Миграция `getActiveAccountSheetV1_`

## 1. Полный исходный код

Текущая реализация из `03_Geometry.js`:

```javascript
function getActiveAccountSheetV1_() {

  const sheet = SpreadsheetApp
    .getActiveSpreadsheet()
    .getActiveSheet();

  const name = sheet.getName();

  if (name === "ACC_TEMPLATE") {
    return sheet;
  }

  if (name === "ACCOUNTS") {
    throw new Error("Откройте лист аккаунта.");
  }

  if (!name.startsWith("ACC_")) {
    throw new Error(`Лист "${name}" не является листом аккаунта.`);
  }

  return sheet;
}
```

## 2. Используемые глобальные константы

Проектные глобальные константы функция **не использует**.

Вместо них непосредственно в коде зашиты следующие значения:

| Значение | Роль | Предпочтительный источник после миграции |
|---|---|---|
| `"ACC_TEMPLATE"` | Имя допустимого листа-шаблона | `SHEETS.TEMPLATE` |
| `"ACCOUNTS"` | Имя служебного листа, который нельзя считать листом аккаунта | `SHEETS.ACCOUNTS` |
| `"ACC_"` | Префикс имени листа аккаунта | Новая именованная константа контекста/листов |
| `"Откройте лист аккаунта."` | Текст ошибки для листа `ACCOUNTS` | Константа сообщений, если сообщения централизуются |
| `` `Лист "${name}" не является листом аккаунта.` `` | Текст ошибки для недопустимого листа | Фабрика/константа сообщений, если сообщения централизуются |

На момент анализа `SHEETS.TEMPLATE` и `SHEETS.ACCOUNTS` уже объявлены в `00_Constants.js`. Канонической константы для префикса `ACC_` в прочитанной реализации нет.

## 3. Используемые внешние функции

Функция не вызывает другие проектные функции.

Используются встроенные средства JavaScript:

- `String.prototype.startsWith()` — проверка префикса имени листа;
- конструктор `Error` — создание исключения;
- шаблонная строка — формирование сообщения с именем текущего листа.

## 4. Используемые методы `SpreadsheetApp`

| Вызов | Владелец метода | Назначение |
|---|---|---|
| `SpreadsheetApp.getActiveSpreadsheet()` | глобальный сервис `SpreadsheetApp` | Получить активную таблицу |
| `.getActiveSheet()` | объект `Spreadsheet` | Получить активный лист таблицы |
| `sheet.getName()` | объект `Sheet` | Получить имя активного листа |

Прямой метод сервиса `SpreadsheetApp` только один — `getActiveSpreadsheet()`. Остальные два метода вызываются у возвращённых объектов Apps Script Spreadsheet service.

## 5. Скрытые зависимости

1. **Контейнерный контекст Apps Script.** Функция предполагает, что скрипт выполняется в контексте активной Google-таблицы.
2. **Наличие активной таблицы и листа.** Контракт не обрабатывает отсутствие активной таблицы или листа; последующий вызов метода завершится ошибкой среды.
3. **Состояние интерфейса пользователя.** Результат зависит не от аргументов, а от листа, активного в момент выполнения.
4. **Соглашение об именах листов.** Любой лист с префиксом `ACC_` принимается как лист аккаунта, даже если его структура не соответствует шаблону.
5. **Особый статус шаблона.** `ACC_TEMPLATE` разрешён как рабочий лист аккаунта, хотя это шаблон, а не экземпляр аккаунта.
6. **Особая обработка `ACCOUNTS`.** Только этот служебный лист получает отдельное сообщение; остальные служебные листы отклоняются общим правилом.
7. **Регистрозависимость.** Сравнения и `startsWith()` чувствительны к регистру.
8. **Глобальная область Apps Script.** Потребители вызывают функцию напрямую без `import`/`export`; доступность обеспечивается общей глобальной областью файлов проекта.
9. **Синхронный контракт ошибок.** Вызывающие функции не получают `null` или объект результата, а рассчитывают на возврат `Sheet` либо выброшенное исключение.
10. **Права Spreadsheet service.** Выполняющий пользователь и триггер должны иметь доступ к активной таблице.

## 6. Побочные эффекты

Функция не изменяет таблицу, лист, выделение или глобальное состояние проекта.

Наблюдаемые эффекты:

- обращение к текущему состоянию Google Sheets через Spreadsheet service;
- выбрасывание `Error` для `ACCOUNTS` и всех листов, не соответствующих допустимому имени;
- прекращение выполнения вызывающей операции, если исключение не перехвачено.

Таким образом, функция является read-only относительно таблицы, но не является чистой: результат зависит от внешнего активного контекста и она может выбрасывать исключение.

## 8. Необходимые изменения imports/references

В текущей архитектуре Google Apps Script явных импортов и экспортов нет: все объявления верхнего уровня доступны в общей глобальной области проекта.

### Вариант с сохранением имени

Если реализацию физически перенести из `03_Geometry.js` в `14_Validation.js` и сохранить имя `getActiveAccountSheetV1_`, изменения в `05_Dropdowns.js`, `07_Calculations.js` и `13_Groups.js` не требуются. Порядок файлов также не влияет на доступность function declaration в стандартной глобальной модели Apps Script.

Потребуется:

- удалить исходное объявление из `03_Geometry.js`, чтобы не осталось двух глобальных функций с одинаковым именем;
- добавить единственное объявление в `14_Validation.js`;
- заменить строковые имена листов на `SHEETS.TEMPLATE` и `SHEETS.ACCOUNTS`;
- определить канонический источник префикса `ACC_` до его замены.

### Вариант с переименованием или namespace

Если при переносе функция получит новое имя либо станет методом объекта, необходимо изменить все 19 ссылок:

- 2 ссылки в `05_Dropdowns.js`;
- 6 ссылок в `07_Calculations.js`;
- 11 ссылок в `13_Groups.js`.

При введении модульной системы дополнительно понадобятся соответствующие `export`/`import`, однако текущий проект такой системы не использует. В рамках минимальной миграции это изменение не рекомендуется совмещать с переносом ответственности.

## 9. Риски миграции

| Риск | Последствие | Снижение риска |
|---|---|---|
| Одновременное наличие старого и нового объявления | Неочевидное переопределение глобальной функции, зависимость от порядка загрузки | В одном логическом изменении удалить старое объявление и добавить новое |
| Изменение имени функции | Поломка одного или нескольких из 19 вызовов | Сохранить имя на первом этапе либо выполнить полный поиск ссылок после переименования |
| Изменение контракта ошибок | Иное поведение UI-команд и расчётов на недопустимых листах | Сохранить тип исключения и тексты на этапе физического переноса |
| Запрет `ACC_TEMPLATE` | Операции, выполняемые на шаблоне, начнут завершаться ошибкой | Зафиксировать текущий special case отдельным тестом |
| Слишком широкая проверка `ACC_` | Ложноположительное принятие неподходящего листа сохранится | Не менять семантику при переносе; усиление валидации оформить отдельной задачей |
| Замена literals на неверные константы | Отличие имени листа и регрессия проверок | Проверить значения `SHEETS.TEMPLATE` и `SHEETS.ACCOUNTS` |
| Добавление новой константы префикса без согласования архитектуры | Дублирование источников истины | Разместить её в каноническом объекте конфигурации листов/контекста |
| Ошибочное ожидание импорта | Лишнее усложнение или несовместимый синтаксис для Apps Script | Сохранить текущую глобальную модель в рамках этой миграции |
| Неполная ручная проверка вызовов | Скрытая регрессия в Dropdowns, Calculations или Groups | Повторить проектный поиск и выполнить сценарии всех трёх модулей |
| Пустой текущий `14_Validation.js` | Нет готовых соглашений о структуре и API модуля | Сначала определить ответственность Validation и документировать контракт функции |

5. В той же логической правке удалить реализацию из `03_Geometry.js`, исключив дублирование глобального объявления.
6. Не менять вызовы в `05_Dropdowns.js`, `07_Calculations.js` и `13_Groups.js`, если имя сохранено. Если принято переименование, атомарно обновить все 19 ссылок.
7. Повторить поиск `getActiveAccountSheetV1_` по всему проекту: должно остаться одно объявление и ожидаемые ссылки потребителей.
8. Выполнить статическую проверку на отсутствие зависимости Geometry от функции валидации.
9. Проверить четыре контекстных сценария в Google Sheets и отдельно операции Dropdowns, Calculations и Groups.
10. Оформить перенос одним логическим коммитом; затем выполнить `clasp push` и финальную проверку в Google Sheets согласно workflow проекта.

Рекомендуемая граница задачи: сначала выполнить только перенос ответственности с сохранением поведения. Переименование, namespace, усиление проверки структуры листа и централизацию сообщений проводить отдельными изменениями, чтобы уменьшить риск регрессии.
