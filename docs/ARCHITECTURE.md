# ACC KPI Framework

# Архитектура проекта

Версия: 2.0.0-alpha

Статус: Approved

Последнее обновление: 2026-07-16

---

# 1. Назначение

ACC KPI Framework — система управления KPI, спринтами, гипотезами и аккаунтами,
реализованная на Google Sheets и Google Apps Script.

Проект развивается как программный framework, а не как набор несвязанных
скриптов.

---

# 2. Главный архитектурный принцип

Любое знание о системе должно иметь единственный источник истины.

Запрещается дублировать:

- названия листов;
- статусы;
- результаты;
- бизнес-коэффициенты;
- координаты;
- размеры блоков;
- смещения;
- геометрию шаблона.

---

# 3. Архитектурные слои

Проект разделяется на четыре базовых слоя:

1. Config
2. Constants
3. Layout
4. Geometry

Остальные модули используют эти слои, но не дублируют их данные.

---

# 4. Config

## Назначение

Config содержит техническую конфигурацию проекта.

## Содержит

- названия листов;
- версию приложения;
- версию шаблона;
- технические параметры;
- системные настройки.

## Примеры сущностей

- `SHEETS`
- `APP_VERSION`
- `TEMPLATE_VERSION`

## Запрещено

- бизнес-статусы;
- бизнес-коэффициенты;
- координаты;
- размеры блоков;
- вычисления;
- обращения к `SpreadsheetApp`.

---

# 5. Constants

## Назначение

Constants содержит неизменяемые бизнес-значения.

## Содержит

- статусы гипотез;
- результаты гипотез;
- бизнес-коэффициенты;
- форматы;
- цвета интерфейса;
- значения по умолчанию.

## Примеры сущностей

- `STATUS`
- `RESULT`
- `BUSINESS`
- `COLORS`
- `FORMATS`
- `DEFAULTS`

## Запрещено

- названия листов;
- координаты;
- номера строк;
- номера столбцов;
- размеры блоков;
- вычисляемые значения;
- обращения к `SpreadsheetApp`.

---

# 6. Layout

## Назначение

Layout является декларативным описанием шаблона Google Sheets.

## Содержит

- количество месяцев;
- количество спринтов;
- количество гипотез;
- количество строк KPI;
- структуру паспорта;
- структуру квартала;
- структуру месяца;
- структуру спринта;
- структуру гипотезы;
- смещения блоков;
- размеры блоков;
- высоты строк;
- ширины столбцов;
- координаты базовых элементов;
- объединения ячеек.

## Примеры сущностей

- `LAYOUT.SHEET`
- `LAYOUT.PASSPORT`
- `LAYOUT.QUARTER`
- `LAYOUT.MONTH`
- `LAYOUT.SPRINT`
- `LAYOUT.HYPOTHESIS`
- `LAYOUT.SUMMARY`
- `LAYOUT.DIRECTORY`

## Правило

Layout описывает шаблон, но не вычисляет реальные диапазоны для конкретного
месяца или спринта.

## Запрещено

- бизнес-расчёты;
- чтение данных из таблицы;
- изменение данных;
- обращения к `SpreadsheetApp`;
- локальные копии статусов и результатов.

---

# 7. Geometry

## Назначение

Geometry преобразует декларативное описание `LAYOUT` в реальные координаты и
диапазоны.

## Содержит функции

- получения геометрии квартала;
- получения геометрии месяца;
- получения геометрии спринта;
- получения строк гипотез;
- получения диапазонов KPI;
- получения диапазонов итогов;
- получения ячеек паспорта;
- вычисления динамических шагов блоков.

## Примеры API

- `getQuarterLayoutV1_()`
- `getMonthLayoutV1_(monthIndex)`
- `getSprintLayoutV1_(monthIndex, sprintIndex)`
- `getSprintStepV1_()`
- `getPassportLayoutV1_()`

## Правило

Рабочие модули не вычисляют координаты самостоятельно.

## Запрещено

- бизнес-расчёты;
- создание UI;
- форматирование;
- запись данных;
- хранение статусов и результатов.

---

# 8. Builder

## Назначение

Builder создаёт и форматирует структуру Google Sheets.

## Разрешено

- создание блоков;
- объединение ячеек;
- установка высот и ширин;
- установка цветов;
- установка границ;
- установка подписей;
- создание заголовков.

## Обязательные зависимости

Builder получает:

- технические параметры из Config;
- цвета и форматы из Constants;
- описание шаблона из Layout;
- реальные координаты через Geometry.

## Запрещено

- бизнес-расчёты;
- подсчёт результатов;
- определение статусов;
- собственные координаты;
- собственные копии цветов и названий листов.

---

# 9. Calculations

## Назначение

Calculations выполняет бизнес-расчёты.

## Содержит

- расчёт итогов спринта;
- расчёт итогов месяца;
- расчёт итогов квартала;
- расчёт прогресса;
- расчёт KPI;
- распределение KPI по месяцам.

## Обязательные зависимости

Calculations использует:

- бизнес-значения из Constants;
- диапазоны и координаты через Geometry.

## Запрещено

- прямые номера строк и столбцов;
- создание интерфейса;
- объединение ячеек;
- установка цветов;
- локальные копии бизнес-коэффициентов.

---

# 10. Events

## Назначение

Events содержит только обработчики событий.

## Примеры

- `onEdit`
- `onOpen`

## Правило

Обработчик определяет событие и передаёт выполнение профильному модулю.

## Запрещено

- сложные расчёты;
- построение шаблона;
- хранение геометрии;
- дублирование бизнес-логики.

---

# 11. Dropdowns

## Назначение

Dropdowns создаёт правила проверки данных.

## Обязательные зависимости

- Config — имена листов;
- Constants — допустимые значения;
- Geometry — диапазоны установки.

## Запрещено

- прямые координаты;
- локальные массивы статусов;
- локальные массивы результатов.

---

# 12. Accounts

## Назначение

Accounts управляет созданием, регистрацией и обслуживанием аккаунтов.

## Обязательные зависимости

- Config — имена листов;
- Geometry — паспорт и рабочие диапазоны;
- Builder — построение структуры;
- Dropdowns — установка проверок данных.

## Запрещено

- собственная геометрия паспорта;
- жёстко заданные имена листов;
- дублирование Builder.

---

# 13. Progress

## Назначение

Progress отвечает за визуальное представление прогресса.

## Обязательные зависимости

- Constants — цвета;
- Geometry — диапазоны;
- Calculations — рассчитанные значения.

## Запрещено

- собственные бизнес-расчёты;
- жёстко заданные координаты;
- собственная палитра вне Constants.

---

# 14. Directory

## Назначение

Directory предоставляет доступ к справочникам.

## Содержит

- KPI;
- сотрудников;
- аккаунты;
- допустимые значения;
- параметры распределения KPI.

## Правило

Имя листа справочника берётся из Config.

---

# 15. Utilities

## Назначение

Utilities содержит универсальные вспомогательные функции.

## Разрешено

- безопасное объединение;
- форматирование диапазонов;
- преобразование значений;
- общие проверки.

## Запрещено

- бизнес-логика;
- координаты конкретного шаблона;
- названия конкретных листов.

---

## 16. Направление зависимостей

Разрешённое направление:

```text
Config
   ↓
Constants
   ↓
Layout
   ↓
Geometry
   ↓
Builder / Dropdowns / Calculations / Accounts / Progress
   ↓
Events / Menu
```

Допускается прямое использование `Config` и `Constants` профильными модулями.

---

## 17. Запрещённые зависимости

Запрещается:

```text
Layout → SpreadsheetApp
Layout → Calculations
Geometry → Builder
Geometry → Calculations
Calculations → Builder
Calculations → прямой Layout без Geometry
Builder → бизнес-расчёты
Events → сложная бизнес-логика
```

---

## 18. Распределение текущих глобальных объектов

### Остаются в Config

- `SHEETS`

### Остаются в Constants

- `STATUS`
- `RESULT`
- `BUSINESS`
- `COLORS`

### Переносятся в Layout

- `PASSPORT`
- `HYP`
- `SPRINT`
- `MONTH`
- `QUARTER`

После миграции старые глобальные геометрические объекты удаляются из
`00_Constants.js`.

---

## 19. Каноническая терминология

Для поля `M6` используется термин:

```text
MANAGER
```

Пользовательская подпись:

```text
Ответственный
```

Глобальный ключ `EMPLOYEE` не используется для поля паспорта.

---

## 20. KPI-строки

Количество строк KPI не должно определяться несколькими независимыми числами.

Единственный источник:

```text
LAYOUT.QUARTER.KPI_COUNT
```

Окончательное значение должно быть подтверждено по действующему шаблону перед
рефакторингом Builder и Dropdowns.

---

## 21. Листы KPI и справочника

Листы:

```text
KPI
90_DIRECTORY
```

считаются разными сущностями до отдельного подтверждения их назначения.

Запрещается создавать alias между ними без проверки бизнес-логики.

---

## 22. Правила миграции

Миграция выполняется поэтапно:

1. Config и Constants.
2. Layout.
3. Geometry.
4. Builder.
5. Dropdowns.
6. Calculations.
7. Accounts.
8. Events.
9. Progress.
10. Финальное удаление устаревших объектов.

На каждом этапе:

- сохраняется совместимость;
- выполняется Git commit;
- выполняется `clasp push`;
- проводится проверка в Google Sheets.

---

## 23. Definition of Done архитектуры v2.0

Архитектура считается завершённой, если:

- имена листов определены только в Config;
- бизнес-значения определены только в Constants;
- структура шаблона определена только в Layout;
- реальные координаты выдаёт только Geometry;
- Builder не выполняет расчёты;
- Calculations не знает координат;
- Dropdowns не содержит локальных статусов;
- Accounts не содержит геометрии паспорта;
- Events делегирует бизнес-логику;
- в рабочих функциях отсутствуют магические координаты.
