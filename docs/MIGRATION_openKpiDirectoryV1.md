# Миграция `openKpiDirectoryV1`

## 1. Полный исходный код `openKpiDirectoryV1`

Текущая реализация из `03_Geometry.js`:

```javascript
function openKpiDirectoryV1() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const sheet = ss.getSheetByName('KPI');

  if (!sheet) {
    SpreadsheetApp.getUi().alert('Лист "KPI" не найден.');
    return;
  }

  sheet.activate();
  sheet.setActiveSelection('A1');
}
```

Функция не выполняет геометрических вычислений и не использует `LAYOUT`. Она является пользовательской навигационной командой.

## 2. Используемые глобальные константы

В текущей реализации проектные глобальные константы **не используются**. Имя листа дважды задано строковым литералом `"KPI"`:

```javascript
ss.getSheetByName('KPI');
SpreadsheetApp.getUi().alert('Лист "KPI" не найден.');
```

Это не соответствует заданному каноническому справочнику. В `00_Constants.js` уже существует единственный допустимый источник имени:

```javascript
const SHEETS = {
  DIRECTORY: "90_DIRECTORY",
  ACCOUNTS: "ACCOUNTS",
  TEMPLATE: "ACC_TEMPLATE",
  ACCOUNT_PREFIX: "ACC_",
};
```

После миграции функция должна использовать только:

```javascript
SHEETS.DIRECTORY
```

Ожидаемые обращения:

```javascript
const sheet = ss.getSheetByName(SHEETS.DIRECTORY);

SpreadsheetApp.getUi().alert(
  `Лист "${SHEETS.DIRECTORY}" не найден.`
);
```

Создавать константу или alias для листа `KPI` нельзя: согласно `docs/ARCHITECTURE.md`, `KPI` и `90_DIRECTORY` считаются разными сущностями, а каноническим справочником в этой задаче задан `90_DIRECTORY`.

## 3. Методы `SpreadsheetApp`, `Spreadsheet`, `Sheet` и `Range`

| Вызов | Владелец | Назначение |
|---|---|---|
| `SpreadsheetApp.getActiveSpreadsheet()` | сервис `SpreadsheetApp` | Получить активную таблицу |
| `ss.getSheetByName(...)` | объект `Spreadsheet` | Найти лист по имени |
| `SpreadsheetApp.getUi()` | сервис `SpreadsheetApp` | Получить UI активной таблицы |
| `.alert(message)` | объект `Ui` | Показать модальное предупреждение |
| `sheet.activate()` | объект `Sheet` | Сделать найденный лист активным |
| `sheet.setActiveSelection('A1')` | объект `Sheet` | Установить активное выделение в `A1` |

Методы `SpreadsheetApp.setActiveSheet()` и методы `Range` функция не использует. В частности, `A1` передаётся строкой непосредственно в `Sheet.setActiveSelection()`, поэтому отдельный объект `Range` не создаётся.

## 5. Передаётся ли имя функции строкой

**Да.** В `09_Menu.js` имя функции передаётся в Apps Script UI как строка:

```javascript
.addItem('Справочник', 'openKpiDirectoryV1')
```

Это означает, что `openKpiDirectoryV1` является публичной глобальной точкой входа. Google Apps Script разрешает обработчик строки только по точному имени доступной top-level функции. Статический анализ обычных вызовов может пропустить такую зависимость.

Физический файл, содержащий функцию, значения не имеет; имя и глобальная доступность имеют.

## 6. Параметры и возвращаемое поведение

- **Параметры:** отсутствуют.
- **Успешный путь:** явного `return` нет; функция возвращает `undefined` после активации листа и выбора `A1`.
- **Лист отсутствует:** после показа alert выполняется `return;`, то есть также возвращается `undefined`.
- **Исключения:** функция сама не выбрасывает прикладной `Error`; ошибки сервисов Apps Script могут распространяться наружу.

Функция не возвращает объект `Sheet`, признак успеха или результат alert.

## 7. UI-поведение

### При наличии листа

1. Находит лист справочника.
2. Переключает интерфейс Google Sheets на этот лист.
3. Устанавливает активное выделение `A1`.
4. Не показывает сообщения.

### При отсутствии листа

1. Остаётся на текущем листе.
2. Показывает модальное предупреждение.
3. После закрытия предупреждения завершает выполнение.

После перехода на `SHEETS.DIRECTORY` пользовательский пункт «Справочник» должен открывать `90_DIRECTORY`, а не отдельный/устаревший лист `KPI`.

## 8. Ошибки и поведение при отсутствии листа

Текущее поведение:

```text
Поиск: KPI
Alert: Лист "KPI" не найден.
Return: undefined
```

Каноническое поведение после миграции:

```text
Поиск: 90_DIRECTORY
Alert: Лист "90_DIRECTORY" не найден.
Return: undefined
```

Функция не должна:

- пытаться создать отсутствующий лист;
- искать fallback-лист `KPI`;
- выбрасывать новый прикладной `Error` вместо alert;
- активировать другой лист;
- создавать новую константу.

Замена литерала `KPI` на `SHEETS.DIRECTORY` меняет фактическую цель навигации, но это обязательное исправление к каноническому контракту задачи, а не произвольное переименование.

## 9. Побочные эффекты

### Активный лист

При успехе `sheet.activate()` меняет активный лист таблицы на `90_DIRECTORY`. При отсутствии листа активный лист не меняется.

### Активный диапазон

После успешного вызова активным диапазоном/выделением становится ячейка `A1` на `90_DIRECTORY`.

### Alerts

Alert показывается только если `ss.getSheetByName(SHEETS.DIRECTORY)` вернул `null`. Это модальное UI-действие, ожидающее взаимодействия пользователя.

### Selection

`sheet.setActiveSelection('A1')` заменяет прежнее выделение на целевом листе. Предыдущее пользовательское выделение не сохраняется и не восстанавливается.

Функция не изменяет значения, формулы, форматирование, структуру листов или данные кэша Directory.

## 10. Скрытые зависимости

1. Скрипт выполняется в UI-контексте активной Google-таблицы.
2. Пользователь имеет доступ к таблице и листу справочника.
3. В таблице существует лист с точным каноническим именем `SHEETS.DIRECTORY`.
4. `SHEETS` загружен в общей глобальной области Apps Script.
5. Функция доступна как top-level global с точным именем `openKpiDirectoryV1`.
6. Пункт меню хранит имя обработчика строкой и не проверяется системой импортов.
7. Меню создаётся через `onOpen()` и `buildUserMenuV1_()` до пользовательского вызова.
8. Код предполагает интерактивный запуск; `SpreadsheetApp.getUi()` непригоден для некоторых неинтерактивных контекстов/триггеров.
9. Выделение `A1` зашито в UI-контракт функции и не вынесено в конфигурацию.
10. Текущая реализация ошибочно зависит от существования листа `KPI`; канонический контракт зависит от `90_DIRECTORY`.
11. Функция не проверяет, скрыт ли лист. Поведение активации скрытого листа зависит от состояния Google Sheets и может завершиться сервисной ошибкой.
12. Внешние триггеры или макросы могут ссылаться на публичное имя, хотя проектный поиск их не видит.

## 11. Риски переноса из `03_Geometry.js` в `09_Menu.js`

| Случайно изменить имя | Пункт меню перестанет вызывать обработчик | Сохранить `openKpiDirectoryV1` дословно |

| Сохранить литерал `KPI` | Команда продолжит открывать неверную сущность | Использовать только `SHEETS.DIRECTORY` в поиске и сообщении |

## 12. Изменения при сохранении имени функции

Если имя `openKpiDirectoryV1` сохраняется, изменения потребителя не нужны:

```javascript
.addItem('Справочник', 'openKpiDirectoryV1')
```

Для миграции в `09_Menu.js` потребуется:

1. Удалить полное объявление из `03_Geometry.js`.
2. Добавить одно top-level объявление в `09_Menu.js`.
3. Сохранить отсутствие параметров и возврат `undefined`.
4. Сохранить alert + `return` при отсутствии листа.
5. Использовать `ss.getSheetByName(SHEETS.DIRECTORY)`.
6. Формировать сообщение отсутствия листа через `SHEETS.DIRECTORY`.

8. Не менять строковую регистрацию пункта меню.

Явные `import`/`export` не нужны: проект использует общую глобальную область Google Apps Script.

## 13. Изменения при переименовании функции

Если функция получает новое имя, необходимо как минимум атомарно изменить два места:

1. Имя top-level function declaration.
2. Второй аргумент пункта меню в `09_Menu.js`:

```javascript

```

Дополнительно нужно проверить:

- макросы;
- внешние вызовы Apps Script API;
- документацию и пользовательские инструкции.

Эти зависимости могут не находиться обычным поиском репозитория. Переименование не требуется для устранения архитектурного нарушения и не должно совмещаться с физическим переносом.

## 14. Нужен ли wrapper для обратной совместимости

При сохранении имени `openKpiDirectoryV1` wrapper **не нужен**. Физическое расположение функции не является частью публичного контракта Apps Script.

При переименовании wrapper может быть нужен:

```javascript
function openKpiDirectoryV1() {
  return newFunctionName();
}
```

Он оправдан, если существуют внешние строковые назначения, которые нельзя обновить атомарно. Если единственный потребитель — обнаруженный пункт меню и он обновляется одновременно, технической необходимости в wrapper нет. Однако в текущей задаче безопасное решение — не переименовывать функцию вообще.

Wrapper не должен оставаться в Geometry: иначе модуль сохранит чужую публичную ответственность. Если он когда-либо потребуется, его следует размещать рядом с новым навигационным обработчиком.

## 15. Целевой модуль: `09_Menu.js` или другой существующий модуль

### `03_Geometry.js`

Однозначно неверное место. Функция не использует `LAYOUT`, не вычисляет координаты и выполняет UI-навигацию.

### `15_Directory.js`

Также не оптимальное место. Directory отвечает за доступ, нормализацию и кэширование данных справочников. `openKpiDirectoryV1()` не читает данные справочника и меняет UI-состояние.

### `09_Menu.js`

Это утверждённая текущей документацией цель: `docs/GEOMETRY_API.md` прямо назначает функцию в `09_Menu.js` и относит к ответственности Menu обработку пользовательских команд и открытие служебных листов. Для ближайшей миграции это совместимый и минимальный вариант.

### `Navigation.js`

С точки зрения строгого правила `docs/CODING_STANDARD.md` — «Navigation содержит только функции навигации» — наиболее чистый долгосрочный дом функции именно `Navigation.js`. Этот файл уже существует и сейчас пуст. Тогда `09_Menu.js` только регистрирует строковый обработчик, а Navigation реализует переход.

**Архитектурное заключение:** функция должна покинуть Geometry. В рамках уже принятого плана ARCH-006 её допустимо перенести в `09_Menu.js` без изменения имени. При следующем выделении полноценного Navigation-слоя её следует разместить в `Navigation.js`; перенос в `15_Directory.js` не рекомендуется.
