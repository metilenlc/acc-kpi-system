# Миграция `getKpiDictionaryV1_`

## 1. Полный исходный код `getKpiDictionaryV1_`

Текущая реализация из `03_Geometry.js`:

```javascript
function getKpiDictionaryV1_() {
  if (KPI_DICTIONARY_V1) {
    return KPI_DICTIONARY_V1;
  }

  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const sheet = ss.getSheetByName(SHEETS.DIRECTORY);

  if (!sheet) {
    throw new Error(`Лист "${SHEETS.DIRECTORY}" не найден.`);
  }

  const cfg = LAYOUT.DIRECTORY.KPI;
  const lastRow = sheet.getLastRow();

  if (lastRow < cfg.FIRST_ROW) {
    return {};
  }

  const rowCount = lastRow - cfg.FIRST_ROW + 1;

  const values = sheet
    .getRange(
      cfg.FIRST_ROW,
      cfg.FIRST_COLUMN,
      rowCount,
      cfg.COLUMN_COUNT
    )
    .getValues();

  const dict = {};

  values.forEach(row => {
    const kpi = String(row[0] || '').trim();

    if (!kpi) return;

    dict[kpi] = {
      unit: row[1],
      aggregation: row[2],
      distribution: row[3] || 'UNIFORM',

      k1: Number(row[4]) || 1,
      k2: Number(row[5]) || 1,
      k3: Number(row[6]) || 1
    };
  });

  KPI_DICTIONARY_V1 = dict;

  return dict;
}
```


Его текущее объявление в `00_Constants.js`:

```javascript
  DIRECTORY: "90_DIRECTORY",
  ACCOUNTS: "ACCOUNTS",
```

## 4. Используемые ключи `LAYOUT`

Функция получает конфигурацию одним обращением:

```javascript

DIRECTORY: {
  KPI: {
    FIRST_ROW: 2,
    FIRST_COLUMN: 18,
```

Используются три конечных ключа:

|---|---:|---|

| `LAYOUT.DIRECTORY.KPI.FIRST_COLUMN` | `18` | Первая колонка диапазона, колонка R |
| `LAYOUT.DIRECTORY.KPI.COLUMN_COUNT` | `8` | Ширина читаемого диапазона, R:Y |

## 6. Точная структура читаемого диапазона

Диапазон формируется так:

```javascript
sheet.getRange(2, 18, lastRow - 2 + 1, 8)
```

В координатах A1 это диапазон:

```text
R2:Y{lastRow}
```

Структура каждой прочитанной строки:

| Индекс массива | Колонка листа | Поле результата | Обработка |
|---:|---|---|---|
| `row[0]` | R | Ключ словаря — имя KPI | `String(value || '').trim()`; пустой KPI пропускается |
| `row[1]` | S | `unit` | Без преобразования |
| `row[2]` | T | `aggregation` | Без преобразования |
| `row[3]` | U | `distribution` | Falsy-значение заменяется на `"UNIFORM"` |
| `row[4]` | V | `k1` | `Number(value) || 1` |
| `row[5]` | W | `k2` | `Number(value) || 1` |
| `row[6]` | X | `k3` | `Number(value) || 1` |
| `row[7]` | Y | Не используется | Значение читается, но игнорируется |

Нижняя граница определяется `sheet.getLastRow()` для всего листа, а не последней заполненной строкой именно колонок R:Y. Поэтому данные в других колонках ниже справочника расширяют читаемый диапазон дополнительными пустыми строками.

Если имена KPI повторяются, более поздняя строка перезаписывает более раннюю запись с тем же нормализованным ключом.

## 7. Значение полей возвращаемого словаря

Результат имеет форму:

```javascript
{
  "Название KPI": {
    unit,
    aggregation,
    distribution,
    k1,
    k2,
    k3
  }
}
```

### `unit`

Единица измерения KPI из колонки S. Текущий потребитель сравнивает `String(unit).trim()` со знаком `%`. Для процентного KPI месячные планы форматируются с двумя знаками после запятой; для остальных — как целые значения.

### `aggregation`

Режим агрегации KPI из колонки T: метаданные о способе сведения значений KPI. В текущем JavaScript-коде поле возвращается, но ни одним потребителем не читается. Допустимые значения и алгоритм агрегации в проанализированных файлах не определены, поэтому конкретную семантику (`SUM`, `AVG` и т. п.) текущий код не гарантирует.

### `distribution`

Код способа распределения квартального плана по месяцам из колонки U. Сейчас `calculateKpiMonthPlansV1()` передаёт его в `calculateMonthPlanV1_()`:

- `UNIFORM` — равномерное распределение по трём месяцам;
- `GROWTH10` — второй месяц составляет 110% первого, третий получает остаток квартального значения;
- любое неизвестное значение попадает в ветку `default` и фактически обрабатывается как `UNIFORM`.

Пустое/falsy-значение в справочнике заменяется на `UNIFORM` ещё при построении словаря.

### `k1`

Числовой коэффициент из колонки V, предположительно для первого периода/месяца. Нормализуется через `Number()` с fallback `1`. Текущий расчёт распределения это поле не использует.

### `k2`

Числовой коэффициент из колонки W, предположительно для второго периода/месяца. Нормализуется через `Number()` с fallback `1`. Текущий расчёт распределения это поле не использует.

### `k3`

Числовой коэффициент из колонки X, предположительно для третьего периода/месяца. Нормализуется через `Number()` с fallback `1`. Текущий расчёт распределения это поле не использует.

Назначение `k1–k3` как коэффициентов периодов следует из имён и расположения полей, но алгоритм их применения в текущем проекте отсутствует. Это архитектурное предположение, а не подтверждённый исполняемым кодом контракт.

## 9. Поведение кэша и риски инвалидации

Кэш ленивый:

1. До первого успешного чтения `KPI_DICTIONARY_V1 === null`.
2. При truthy-значении переменной функция немедленно возвращает тот же объект.
3. После обработки строк ссылка на `dict` присваивается `KPI_DICTIONARY_V1`.
4. Все последующие вызовы в том же живом глобальном контексте возвращают эту же ссылку без чтения листа.

Риски:

- в проекте нет функции сброса или обновления `KPI_DICTIONARY_V1`;
- изменение `90_DIRECTORY` после первого чтения может не попасть в последующие расчёты того же выполнения/сохранившегося глобального контекста;
- Apps Script не следует рассматривать как гарантированное долговременное хранилище глобального кэша: новый запуск обычно создаёт новый контекст, но время жизни экземпляра среды не является явным контрактом этой функции;
- возвращается исходный кэшированный объект, поэтому потребитель может случайно изменить словарь или вложенные объекты для последующих вызовов;
- ошибки чтения не кэшируются;
- нет привязки к Spreadsheet ID: функция полагается на активную таблицу, а кэш не хранит идентификатор источника;
- пустой объект `{}` является truthy, поэтому словарь без валидных KPI, однажды присвоенный кэшу, тоже блокирует повторное чтение.

## 10. Поведение при пустом справочнике

Существуют два разных сценария.

### На листе нет строк данных

Если `sheet.getLastRow() < 2`, функция немедленно возвращает новый `{}`:

```javascript
if (lastRow < cfg.FIRST_ROW) {
  return {};
}
```

Этот результат **не записывается** в `KPI_DICTIONARY_V1`. Повторный вызов снова обратится к листу.

### Строки существуют, но KPI в колонке R пусты

Диапазон читается, каждая строка пропускается по `if (!kpi) return`, после чего пустой `dict` записывается в кэш. Повторный вызов вернёт кэшированный `{}` без обращения к листу.

Если лист `90_DIRECTORY` отсутствует, функция не возвращает пустой словарь, а выбрасывает:

```text
Error: Лист "90_DIRECTORY" не найден.
```

## 11. Нормализация данных

### Ключ KPI

```javascript
String(row[0] || '').trim()
```

- значение преобразуется в строку;
- falsy-значения заменяются пустой строкой;
- удаляются пробелы с начала и конца;
- пустые ключи пропускаются;
- регистр сохраняется, поэтому `ER` и `er` — разные ключи;
- внутренние повторные пробелы не нормализуются.

### `unit` и `aggregation`

Возвращаются без преобразований. Пробелы, регистр, тип значения и пустые ячейки сохраняются как пришли из `getValues()`.

### `distribution`

```javascript
row[3] || 'UNIFORM'
```

Пустая строка и другие falsy-значения заменяются на `UNIFORM`. Непустое значение не преобразуется в строку, не обрезается и не приводится к верхнему регистру. Например, `" uniform "` не совпадёт с `"UNIFORM"`, но нижележащий `default` всё равно даст равномерное распределение.

### `k1`, `k2`, `k3`

```javascript
Number(value) || 1
```

- числовые строки преобразуются в числа;
- пустая ячейка превращается в `0`, затем заменяется на `1`;
- `NaN` заменяется на `1`;
- фактический ноль также заменяется на `1`, поэтому коэффициент `0` сохранить нельзя;
- отрицательные и ненулевые дробные значения сохраняются;
- `Infinity` сохраняется, так как является truthy.

## 12. Скрытые зависимости

1. Выполнение в контейнерном контексте активной Google-таблицы.
2. Наличие листа с точным именем `SHEETS.DIRECTORY` (`90_DIRECTORY`).
3. Соответствие физической схемы R:Y структуре, предполагаемой индексами `row[0]..row[7]`.
4. Заголовок находится в первой строке, данные начинаются со строки 2.
5. Последняя строка всего листа адекватно ограничивает справочник KPI.
6. Имена KPI в квартальном блоке после `String(...).trim()` точно совпадают с ключами словаря с учётом регистра.
7. Значения `distribution` соответствуют режимам, которые понимает `calculateMonthPlanV1_()`.
8. Единица процентных KPI после trim равна ровно `%`.
9. Google Apps Script предоставляет общую глобальную область файлов; явных `import`/`export` нет.
10. Порядок загрузки файлов не должен создавать второе объявление `KPI_DICTIONARY_V1` или `getKpiDictionaryV1_`.
11. Потребители не мутируют возвращённый объект.
12. Восьмая колонка Y намеренно зарезервирована или не нужна: сейчас она читается, но не отражается в контракте результата.

## 13. Побочные эффекты

Функция не изменяет содержимое или форматирование Google Sheets и не показывает UI.

Наблюдаемые эффекты:

- читает активную таблицу и лист справочника;
- выполняет чтение диапазона при cache miss;
- присваивает новый объект глобальной переменной `KPI_DICTIONARY_V1`;
- возвращает изменяемую ссылку на кэшированный объект;
- выбрасывает `Error`, если лист справочника отсутствует.

Функция не является чистой: результат зависит от активной таблицы, данных листа и состояния глобального кэша.

| Риск | Последствие | Снижение риска |

## 15. Изменения для переноса в `15_Directory.js` без смены имени и контракта

В текущей модели Google Apps Script явных импортов и экспортов нет. Поэтому при сохранении глобального имени изменения в `07_Calculations.js` не требуются.

Необходимые изменения будущей задачи:

1. В `15_Directory.js` разместить модульный заголовок, описывающий ответственность Directory.
2. Перенести туда полное объявление `let KPI_DICTIONARY_V1 = null;`.
3. Перенести туда функцию `getKpiDictionaryV1_()` без изменения имени, параметров, return-значений, сообщений, нормализации и кэширования.
4. Удалить переменную и функцию из `03_Geometry.js`.
5. Не менять единственный вызов в `07_Calculations.js`.
6. Не создавать новые константы и не менять `SHEETS` или `LAYOUT` в рамках физического переноса.
7. Не оставлять временный wrapper в Geometry: он сохранил бы неправильную зависимость и вторую точку ответственности.
8. Проверить по всему проекту одно объявление функции и одно объявление кэша.

Физическое расположение файла не меняет глобальный контракт Apps Script. Критично лишь отсутствие дублирующих top-level объявлений.

## 16. Нужно ли переносить `KPI_DICTIONARY_V1` вместе с функцией

**Да, обязательно.**

Переменная является внутренним состоянием `getKpiDictionaryV1_()` и не используется никакой другой функцией. Если оставить её в `03_Geometry.js`, Geometry продолжит владеть состоянием Directory и сохранится скрытая межмодульная зависимость. Это нарушит правила «один модуль — одна ответственность» и цель очистки Geometry.

Функцию и кэш следует переносить одним логическим изменением. Имя `KPI_DICTIONARY_V1` на этапе переноса также нужно сохранить, чтобы не совмещать перемещение с рефакторингом контракта состояния.
